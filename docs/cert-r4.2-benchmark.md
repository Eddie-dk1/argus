# CERT r4.2: первый сравнительный эксперимент

> Исторический протокол и результаты соответствующего этапа. Текущий статус —
> [оценка проекта](cert-r4.2-stage-assessment.md); следующий согласованный этап —
> [S4: качество моделей](s4-model-quality-plan.md), ещё не начат. Формулировки
> «следующий»/«пока» в датированных разделах относятся к моменту того этапа.

План зафиксирован 13 ноября 2026 года до новых исследовательских кандидатов и
до оценки реального test. Это продолжение S2: подготовка уже завершена, теперь
нужны результаты моделей. Машиночитаемый [план серии](../configs/cert_r4_2_benchmark_plan_v1.json)
связывает подготовку и [конфигурацию кандидатов](../configs/cert_r4_2_experiment_v1.json)
по SHA-256. Он описывает фиксированную серию, не автоматический поиск S6.

## Четыре последовательных пункта

1. Зафиксировать план и выполнить Random Forest / Isolation Forest с seed 42
   на train/validation; проверить одинаковые примеры, артефакты и reload.
2. Выполнить LSTM-AE с seed 42 на той же подготовке и endpoint cohort.
3. Завершить повторы всех трёх моделей с seeds 7, 21, 42, 84, 168. Seed 42
   повторно не обучать при неизменных конфигурации/коде. Зафиксировать IDs,
   checkpoint и порог каждого кандидата до test; лучший seed не выбирать.
4. Отдельно выполнить frozen final evaluation всех семей/seed, проверить общую
   популяцию, сохранить время inference и ошибки по сценариям. Итоговые таблицы:
   все seed, среднее/std/min/max и ограничения. Релиз v0.3.0 требует отдельной
   сверки release gate, а не объявляется автоматически.

## Зафиксированные условия

- Единица: endpoint активного дня аккаунта с official observable membership.
  Split связанных аккаунтов не меняется: 600/200/200; split seed всегда 42.
- Подготовка: `cert_preparation_8488758ce2e94ed8b57bbb9d10dc651a`, 71 признак,
  окно из пяти активных дней. Все модели оценивают одни endpoint IDs.
- RF: 200 деревьев, max_depth=10, class_weight=balanced, все 199 165 train-дней.
  IF: 200 деревьев, остальные параметры sklearn по умолчанию, только 198 519
  background train-дней. Фактические версии библиотек и параметры сохраняются.
- LSTM: hidden_size=32, learning_rate=0.001, batch_size=128, максимум 10 эпох,
  patience=5. Обучение только на all-background train-окнах. Это пункт 2.
- Одна конфигурация на семейство, без поиска параметров. Threshold percentiles:
  90, 95, 97, 98, 99, 99.5, 99.7, 99.8, 99.9, 99.95, 99.99.
  Выбор по validation F1 → recall → меньшему FPR → меньшему порогу.
  Решение: score ≥ threshold. Label-калибровка IF/LSTM явно supervised.
- Конфигурация, записанная при подготовке, содержит прежнюю сетку порогов.
  Для этой серии обязательно передавать актуальный `--config`: изменение сетки
  разрешено runner и не меняет frozen признаки/split. Хеш выбранного config
  закреплён планом до новых запусков.
- Validation: 64 254 endpoint-дня, 180 positive и 64 074 background;
  prevalence 0,2801%. Test пока закрыт для оценки.
- Последовательные CPU-запуски, sklearn n_jobs=1, OMP/BLAS threads=1.
  Inference benchmark: один прогрев, пять повторов на готовом полном validation
  cohort; tabular — вся матрица, LSTM — batch 128. I/O, подготовка признаков,
  обучение и inference измеряются отдельно. Это не single-item latency.

## Воспроизведение пункта 1

`ARTIFACT_ROOT` — существующий каталог на подключённом SSD,
`CERT_PREPARATION` — каталог указанной подготовки. Перед запуском сверить хеши
плана и config. Команды не открывают `test.csv` и создают новые UUID-каталоги:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
python3 src/experiment.py --root "$ARTIFACT_ROOT" candidate \
  --preparation "$CERT_PREPARATION" --model random_forest \
  --config configs/cert_r4_2_experiment_v1.json

OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
python3 src/experiment.py --root "$ARTIFACT_ROOT" candidate \
  --preparation "$CERT_PREPARATION" --model isolation_forest \
  --config configs/cert_r4_2_experiment_v1.json
```

Все входы, predictions, модели и record-level связи остаются на SSD. В Git —
план, конфигурация и агрегаты. Технический IF с 8 деревьями в сравнении не участвует.

## Ограничения интерпретации

Validation здесь используется для выбора порога, поэтому её метрики —
development-результаты. О качестве на независимом test пока выводов нет.
Метка означает observable membership; background не доказывает безопасность.
История train персональная, held-out использует frozen global fallback — это
сохраняющееся ограничение протокола, а не исправление через test.
Сценарий 3 отсутствует в validation, а test имеет только одну независимую
группу этого сценария. Повторы seed не создают новые независимые инциденты.
