## Преобразования и отсутствие утечки

Вход — завершённая [дневная подготовка](cert-r4.2-day-preparation.md),
все файлы которой сверяются с `complete.json`. Никакого нового split нет:
аккаунты и связанные группы сохраняют назначения пункта 1.

Из 59 raw-признаков получаются 61 базовый числовой признак:

- неотрицательные объёмы, длительности и счётчики преобразуются `log1p`;
- source fractions и `is_weekend` остаются без `log1p`;
- first/last second заменяются sin/cos с периодом 86 400 секунд.

Добавляются 10 признаков истории, итого **71**:

| Признак | Значение до стандартизации |
|---|---|
| prior7/prior30_events_log1p | log1p суммы событий предыдущих активных дней в `[date−7, date)` / `[date−30, date)` |
| prior30_days_log1p | log1p числа наблюдавшихся дней в предыдущие 30 календарных дней |
| history_missing | Нет 5 предыдущих дней в 30-дневной истории для персонального robust profile |
| cold_start | Для train ещё нет персональной истории; для held-out всегда 1 |
| volume_robust_deviation | `(log1p(total_events) − median) / max(IQR, 1e-6)`, clipped в фиксированный диапазон [−20,20] |
| pc/domain/recipient_novel_fraction | Доля уникальных текущих значений, отсутствующих в reference vocabulary; при пустом текущем множестве 0 |
| days_since_previous_active_log1p | log1p календарного разрыва от предыдущего активного дня аккаунта, 0 для первого дня |

Политика явно различает персональную историю train и замороженный fallback:

- **Train:** суммы и персональный robust profile используют только предыдущие
  дни аккаунта; vocabulary — только более ранние дни этого аккаунта.
  Текущий день добавляется в историю после расчёта признаков.
- **Train без достаточной истории:** median/IQR из всех train-дней;
  при отсутствии персонального vocabulary используется общий train vocabulary.
- **Validation/test:** персональные истории и vocabulary не обучаются и не
  накапливаются. Используются общие train median/IQR/vocabulary; rolling counts
  равны 0 с явными `history_missing=1` и `cold_start=1`.
- Календарный разрыв и последовательность ранее наблюдавшихся входных дней
  доступны всем split: это хронология наблюдений, а не подгонка персонального
  профиля или использование прошлых меток.

Общие median/IQR/vocabulary и среднее/std стандартизации рассчитаны **только
на train**, по всем его дням, без чтения label для расчёта признаков. Они являются
batch-fitted состоянием, а не историческими оценками на каждую дату train.
Это offline account-holdout протокол, не доказательство временного прогноза
с обучением исключительно до самой ранней даты validation/test.
Для постоянных колонок scale=1. Все числовые входы сохраняются как float32
при формировании массивов; нечисловые идентификаторы исключены allowlist.

Различие доступности персональной истории train и held-out — ограничение
протокола. Следующая исследовательская серия должна отдельно сравнить режим
полностью global-only и объявленный causal-online режим; сейчас они не смешаны
с основной политикой и не подбираются по test.

## Окна и общая популяция оценки

Окно — 5 последовательных **активных** дней одного аккаунта внутри одного
split. Это не обязательно 5 соседних календарных дней. Дни без событий не
создаются; padding отсутствует. Первые 4 дня каждого аккаунта не входят
в общую оценочную популяцию. Календарный разрыв сохранён отдельным признаком.
Target — observable label последнего дня окна (`endpoint_account_day_observable`).
RF, IF и LSTM оцениваются на одинаковых endpoint item IDs.

RF обучается на всех train-днях. IF — на train-днях с background label.
LSTM — только на окнах, **все дни которых background**. Это условие исключает
окна с положительным днём внутри и нулевым endpoint. Background не означает
независимо доказанную безопасность. Synthetic сохраняет прежнюю endpoint-normal
политику для совместимости с его reference.

## Артефакты и исполнение

`prepare-cert` сохраняет новые `train.csv`, `validation.csv`, `test.csv`,
`feature_state.json` (общие профили, vocabulary и scaler), `contract.json`,
конфигурацию, отчёт eligible/excluded cohorts, provenance и checksum manifest.
UUID-каталог не перезаписывает дневную подготовку.

`history_dependencies.jsonl.gz` фиксирует точные IDs rolling7/30 history,
cutoff, account и тип reference. Для накопленного novelty vocabulary зависимость
определена как все более ранние train-дни этого аккаунта; их полная идентичность
восстанавливается из parent daily preparation и указанного cutoff.
Глобальные references закреплены `feature_state.json`. История может выходить
за пределы пяти дней LSTM. `contract.json` закрепляет путь к родительским
дням и SHA-256 его manifest; сами raw membership-файлы повторно не копируются.

Кандидаты используют существующий общий runner: сохраняют фактические model
inputs, ordered window membership, веса, state, validation scores и выбранный
порог. Кандидат не открывает и не хеширует `test.csv`. Test доступен только
отдельному `final`, где модель/порог не обучаются заново. Реальный test на этапе
технического подключения не оценивается.

```bash
python3 src/experiment.py --root "$ARGUS_DATA_ROOT/cert_r4_2/processed" prepare-cert \
  --days "$CERT_DAYS" --config configs/cert_r4_2_experiment_v1.json

python3 src/experiment.py --root "$ARGUS_DATA_ROOT/cert_r4_2/processed" candidate \
  --preparation "$CERT_PREPARATION" --model isolation_forest \
  --config configs/cert_r4_2_experiment_v1.json
```

В конфигурации CERT сетка percentile thresholds включает 99.5–99.99,
чтобы не ограничивать кандидат искусственно нижней границей около 1% alerts
при доле positive days около 0,3%. Это заранее заданная сетка; модельные
параметры и threshold grid могут меняться в отдельных candidates без
изменения frozen preparation. Порог всё равно выбирается только на validation.

Ограничение сценария 3 сохраняется: validation не содержит независимых групп
этого сценария, test содержит лишь одну. Его качество нельзя считать
надёжно оценённым по множеству независимых эпизодов.

## Проверки

Тесты подтверждают неизменность train-fitted state при изменении held-out
значений, причинность персональной истории при фиксированном общем state,
повторное применение сохранённого state, отказ при пересечении групп,
обучение всех трёх кандидатов без доступного test-файла, строгую фильтрацию
background windows и совпадение endpoint cohorts при final на искусственной
малой fixture. Эти технические тесты не заменяют исследовательские эксперименты.
