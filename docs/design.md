# Argus / Spectra Lab — интерфейс и визуальные правила

Дата: 27 октября 2026 года. Статус: актуальная спецификация будущего UI. Код интерфейса в рамках этой правки не создаётся.

## 1. Направление

Минималистичный тёмный интерфейс с выраженным, но спокойным тёмно-синим оттенком. Ориентиры — сдержанная структура GitHub dark и нейтральная иерархия Vercel/Geist. Это собственная палитра Argus, не копия их брендов или точных токенов.

Содержание, типографика и отступы важнее декоративных графиков. Нейтральный логотип Argus, один sidebar, один header и одно рабочее пространство Spectra Lab. EventLens и названия других набросков не показываются как продукты.

### Значение красного

Красный используется для конкретной проблемы: prediction «Отмечен», failed job, invalid input, превышенный лимит, существенное нарушение целостности. Обычно достаточно точки, короткой подписи, значка или одной аномальной отметки графика.

Красный не используется как цвет логотипа, обычных кнопок, активного меню, slider, ссылок, всех графиков или рамки выбранной строки. Выделение без ошибки — нейтральное/приглушённо-синее. Для опасного действия допустим отдельный danger control с ясным текстом.

Normal/success не означает большую зелёную заливку: нейтральный текст и check/status label достаточны. Не добавлять радугу цветов по модели/действию. Если аналитический график требует нескольких серий, использовать компактную согласованную гамму и прямые подписи; red сохраняет семантическое значение.

## 3. Единственная навигация

1. **Обзор** — эксперимент, метрики, список примеров и переход к разбору.
2. **Подбор моделей** — конфигурации, validation качество, ресурсы и фиксация выбора.
3. **Разбор событий** — источник, окно, признаки, контекст, нормальный ориентир.
4. **Проверка сценариев** — raw patch, пересчёт, исходный/новый score и diff.

«Данные» и «Настройки» допускаются как второстепенные служебные действия. Сравнение моделей размещается внутри обзора/разбора. Карта — последующий режим обзора, не обязательный стартовый экран. Не вводить отдельные EventLens, Causal, Adaptive, Edge или дублирующую группу «Эксперименты» со смешанными смыслами.

В header показывать короткий experiment ID, выбранную модель и понятный источник/режим. Полные hashes, absolute paths и версии открываются по запросу, не занимают каждый экран.

## 4. Основные экраны

### Обзор

Одна компактная строка контекста/показателей и рабочая таблица. Справа — выбранный пример или краткая информация об эксперименте. Primary action «Разобрать событие». Не заполнять экран risk gauges, картой мира, SOC-счётчиками, CPU widgets или неподтверждёнными attack counts.

### Подбор моделей

Короткий study config: модель, стратегия, budget/max trials. Основная область — trials table; справа — выбранная configuration и действие «Зафиксировать модель». Quality/cost graph только при наличии сопоставимых измерений. Failed trial отмечается локально, normal completion нейтрально. Test не является интерактивным фильтром выбора победителя.

### Разбор событий

Заголовок примера, сохранённые результаты моделей, timeline и source inspector. Model inputs выделены отдельно от дополнительной истории. Нижние tabs могут содержать признаки, normal reference и residual matrix. Действия «Найти нормальный пример», «Проверить изменение» и «Экспортировать эпизод» без отдельного бренда EventLens.

### Проверка сценариев

Два сравнимых блока: исходный и изменённый вариант. Редактируются только разрешённые raw fields. Светлая кнопка «Пересчитать». Сравнение чисел/решений имеет один сохранённый threshold; шкалы разных моделей не смешиваются. Новый label — «Неизвестен». Изменение score не подаётся как доказанное предотвращение атаки.

## 5. Компоненты и читаемость

- Flat layout, 1px разделители, небольшие radii 4–8px, без вложенных карточек.
- SF Pro/system sans для русского интерфейса; Geist Sans как вариант при проверенной Cyrillic fallback. SF Mono/Geist Mono для чисел и IDs. Паковать необходимые assets offline.
- Размер обычного UI-текста ориентировочно 14–16px, заголовка 24–30px; не делать всё мелким ради плотности.
- Базовый spacing 8px, рабочие gutters 24–32px, без гигантских маркетинговых отступов.
- Простые единообразные системные/Radix-подобные иконки. Текстовые пункты не требуют декоративного цветного значка.
- Primary action — светлая нейтральная кнопка, secondary — контур/текст. Избегать больших pills, glow, gradients, стекла и тяжёлых теней.
- Таблицы имеют видимый selected state, sort direction, unit labels и понятное missing состояние; длинные values доступны без потери identity.
- Красный или другой цвет дополняется текстом/иконкой. Предусмотреть focus, keyboard navigation, loading, empty, unavailable, disabled и cancel states.
- Проверить layout на 1440×900 и 1280×800, не полагаться на огромный внешний монитор. Широкие таблицы прокручиваются в своей области.
- При reduced motion убрать необязательную анимацию; autoplay/drift не нужен.

## 6. Графики и научная корректность

Каждый график имеет оси/единицы, подписи, cohort/method scope и различает data/model score. Реальные UI charts строятся из сохранённых артефактов, а не повторяют схематичные числа картинок.

UMAP расстояние не является риском, reconstruction residual не равен причине, latency batch не равна single-item response time. Projection фиксирована при смене model coloring; filter/sampling не скрываются.

Истинные labels, predictions и manual notes отображаются отдельно. «Нет оценки» и «Не отмечен» — разные состояния. Не показывать красным всю страницу только потому, что на ней исследуется один flagged example.

## 7. Актуальные и архивные концепты

[Текущий набор](../output/design/spectra-lab-2026-10-27/README.md) показывает четыре раздела в новой палитре. Картинки — будущий интерфейс с демоданными, не реализованная программа. Подготовка плана/дизайна не меняет src, модели или результаты Argus.

[Архив](../output/design/archive/README.md) хранит ранние dashboards и красные макеты от 17.10.2026. Их данные, меню, branding и palette не являются требованиями. Исторические prompts сохраняются дословно для происхождения изображений, но не используются как новые инструкции.

Прежние макеты перемещаются, а не уничтожаются; их можно восстановить. При противоречии изображения и текста руководствоваться этой спецификацией и [единым планом](spectra-lab-implementation-plan.md).

## 8. Основания выбора

Решение пользователя от 27.10.2026: minimal dark navy, red только для конкретных проблем/указаний. Правила minimalist-ui применены к структуре, типографике и отсутствию декоративного шума; его исходная светлая палитра заменена пользовательской тёмной.

Проверенные ориентиры: [Vercel Geist Colors](https://vercel.com/geist/colors) — нейтральные default UI-роли и смысловые scales; [GitHub Primer Color](https://primer.style/product/primitives/color/) — системные цветовые роли.
