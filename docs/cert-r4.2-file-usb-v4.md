# CERT: пункт 3 — generic file/USB deviations

Протокол зафиксирован 14 ноября 2026 года перед новой CERT-серией.
[Bounded plan](../configs/cert_r4_2_file_usb_ablation_v4.json) связывает daily
source и завершённую [CV пункта 2](cert-r4.2-group-cv-v3.md) через SHA-256.
Новые признаки продолжают [причинную историю пункта 1](cert-r4.2-causal-history.md).
Пункт 4 — endpoint-only score/обоснованная архитектура — здесь не выполняется.

## Что проверяется

В пункте 2 персональная история v3 дала умеренный рост RF с дополнительными FP,
ухудшила IF и почти не изменила LSTM. Следующая отдельная гипотеза: общее число
событий может скрывать изменение конкретного типа активности. Добавляются
отклонения `file_events`, `connect_count`, `device_paired_seconds` от прошлого
того же аккаунта; ID, exact filenames/domains и answer-key строки не входят в X.
Эта гипотеза учитывает уже увиденные development/final diagnostics и поэтому
остаётся exploratory. Успех заранее не предполагается.

Три варианта, все RF/IF/LSTM, те же три outer fold и model seed 42:

| Вариант | Признаки | Персональный reference новых deviations |
|---|---|---|
| `causal_all_v3` | прежние 71 | новые признаки отсутствуют; 9 frozen candidates пункта 2 переиспользуются |
| `file_usb_rolling_v4` | прежние 71 + 4 | прошлые активные дни в `[date−30,date)`, минимум 5 |
| `file_usb_frozen_v4` | прежние 71 + 4 | первые 5 уже наблюдавшихся активных дней аккаунта; после этого заморожен |

Объём — **27 assessments, 18 новых fit и 9 переиспользованных кандидатов**.
v3 → rolling проверяет добавление признаков; rolling → frozen меняет только
reference новых признаков. Общее сравнение v3 → frozen объединяет оба эффекта.
Все результаты сохраняются; автоматического выбора победителя или расширения
поиска по outer-метрикам нет.

## Формула и доступность данных

Для каждого из трёх raw volumes:

`deviation = clip((log1p(current) − median(log1p(reference))) / max(IQR(log1p(reference)), 1), −20, 20)`.

Четвёртый новый признак — `file_usb_profile_missing`: 1 при frozen global
fallback, 0 при доступном персональном reference. Порог 5 дней, окно 30 дней,
граница IQR 1 в единицах log1p и clip 20 объявлены до новой серии, без подбора.
Граница IQR защищает от деления на почти нулевую вариативность: умеренное
изменение после серии нулей не должно автоматически попадать в clip 20.
Это инженерная гипотеза, а не параметр, доказанно оптимальный для CERT.

Global fallback для каждого raw volume — median/IQR всех **inner-fit активных
дней**, включая нули и положительные дни. Он заморожен; scaler тоже fit только
на inner fit. Personal reference одинаков во всех ролях: сначала признаки
текущего дня, затем наблюдение этого дня. Ни текущий день, ни будущее не входят
в его персональный reference. Первые пять дней используют только global
fallback; шестой может использовать первые пять. Никакого backfill ранних
строк после появления будущего профиля нет.

Rolling reference после длинного разрыва может снова перейти на fallback.
Frozen reference сохраняется после разрыва и может устареть или включать
положительные дни первых наблюдений. Эти дни не очищаются по истинным labels.
Остальные десять history-признаков v3, включая общий total-event rolling profile
и novelty, остаются прежними даже у frozen file/USB варианта.

Это end-of-day aggregates: `file_events` не доказывает копирование на USB;
`device_paired_seconds` суммирует только сопоставленные Connect/Disconnect
одного PC внутри дня. Пересекающие полночь/непарные соединения не превращаются
в выдуманную полную длительность. Их прежние raw indicators сохраняются.
Offline global reference по всему разрешённому inner fit может включать даты
позже оцениваемого дня: это перенос между аккаунтами, не temporal forecast.

## Протокол и аудит

Популяция — только original primary train: 199 165 активных account-days,
600 аккаунтов/592 группы; 196 765 endpoints, включая 646 observable-positive.
Primary validation/test исключаются до feature building. Общие source files
содержат все роли и проходят verification; это не утверждение, что ни один
test-related байт не читался. Prepared test не создаётся и не оценивается.

Assignments incident-connected groups по содержимому сверяются с
пунктом 2. Preprocessing refit на inner fit; внутренний calibration split,
threshold grid, objective F1 и tie-breakers прежние. RF 200/depth10/balanced,
IF 200, LSTM hidden32/batch128/lr0,001/max10/patience5 и пятидневный mean-MSE
не меняются. Ни дополнительной регуляризации, ни нового score здесь нет.
При добавлении четырёх входов LSTM получает размерность 75 вместо 71; форма
input/output weights и число слагаемых mean-MSE меняются вместе с признаками.
Поэтому абсолютный MSE разных feature policies нельзя ранжировать как качество
detection. Пакет deviations/indicator проверяется совместно: серия не разделяет
индивидуальные эффекты трёх raw volumes и missingness-признака.

До первого fit сохраняются план, source/config/environment snapshots, все
folds, шесть новых preparations и все 27 jobs. Аудитор независимо проверяет
каждую reference membership, cutoff и deviation, fit-only global statistics,
все прежние 71 numerical inputs/scaling, ordered IDs/labels и cohort. Dependency
files сохраняют reference IDs; положительная история не исключается.
Worker запрещает `test.csv` всегда, а `assessment.csv` до завершения candidate.
Повторно используемые v3 checkpoint/threshold сохраняются неизменными; их
результаты должны точно воспроизвести пункт 2.

Отчёт содержит все folds, macro mean/sample SD/min/max, PR-AUC/precision/recall/F1,
FP/FN и сценарный support. Pooled OOF decisions покрывают каждый endpoint один
раз на policy/model; pooled PR/ROC AUC не рассчитывается для разных fold models.

Отдельная post-inference диагностика группирует endpoints по числу **прошлых**
observable-positive дней в `[date−30,date)`: 0, 1–4, ≥5. Показываются raw
deviations и recall/FP fractions, включая длительную положительную историю.
Эти метки нужны только для отчёта после завершения всех inference; они не
являются входами, фильтром истории или критерием выбора. Bins не устанавливают
настоящий момент начала инцидента и не доказывают причинное влияние адаптации.


Повтор команды создаёт отдельную серию; не нужно повторять её ради удобной
метрики. В текущем пункте объявлена одна серия и один model seed.

## Границы вывода

Те же уже изученные development folds не становятся независимым holdout.
Fold SD — описательная вариация зависимых разбиений, не confidence interval.
Background означает отсутствие official observable, а не подтверждённую
безопасность. Сценарий 3 имеет только одну независимую группу в этой популяции.
Для confirmatory утверждения о новой модели нужны независимые принятые данные.

Метод median/IQR описан в [документации RobustScaler](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.RobustScaler.html);
наши log1p, floor/clip и causal references заданы отдельно. Ограничение fit
обучающей частью и разделение calibration/assessment следуют
[правилам предотвращения leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)
и [nested CV](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html).

**RF frozen — перспективный development candidate.** Относительно v3 mean
outer F1 вырос на 0,057254, PR-AUC на 0,030501. Оба показателя выше во всех
трёх folds. В pooled decisions precision 16,56% → 22,05%, recall 38,54% → 39,63%,
FP 1 255 → 905, TP 249 → 256. Это на 350 меньше FP при семи дополнительных
найденных positive days; всё ещё пропущены **390 из 646**. Сценарий 1 ухудшился
с 10/58 до 8/58, сценарий 3 по-прежнему 0/32; общего решения всех сценариев нет.
Rolling RF даёт больший recall 46,90% (303 TP), но 1 393 FP и худший pooled F1
0,258753. В третьем fold rolling F1 упал с 0,252011 до 0,195867 при более высоком

**IF не решена.** Frozen поднимает pooled recall с 2,01% v3 до 8,98%, но FP

**У LSTM нет существенного detection-прогресса.** Rolling повышает macro F1,

имеет нулевой recall. PR-AUC выросла немного, но сценарий 2 остаётся около
6–7% recall. Один лишь новый профиль не исправляет основную проблему LSTM.

**Адаптация не объясняет всё одной причиной.** В stratum ≥5 previous positives
находятся 462 из 646 positive endpoints. Median device-duration deviation у
frozen выше: 0,397380 против rolling 0,161911, но median file/connect deviations
не растёт таким же образом. RF rolling recall в этом stratum выше frozen
(239/462 против 206/462), а IF frozen recall остаётся только 24/462. Искусственный
тест доказывает возможность нормализации устойчивого сдвига rolling-профилем;
эти CERT-срезы не доказывают, что она является единственной причиной FN, или
что frozen лучше по каждому сценарию. Ни один положительный день из истории
не удалялся.

Следующий пункт 4 остаётся отдельным: проверить endpoint-only reconstruction
score LSTM при неизменных labels/cohort/модели и внутренней calibration,
используя результаты этой серии как контекст. Новые архитектуры/регуляризация
по-прежнему требуют отдельной конкретной гипотезы. Никакого автоматического
перехода всех моделей на frozen v4 здесь нет; варианты и старые результаты
сохранены. На завершение этой серии пункты 4–5 не запускались; позднее
[пункт 4](cert-r4.2-model-variants-v5.md) выполнен отдельно. Он переиспользует
эти inputs/controls и не меняет результатов данного feature comparison.
