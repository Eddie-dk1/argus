## Единственное изменение входов

`cert_frozen_global_only_v2` использует один frozen global train-профиль и
vocabulary для всех split, включая train. Персональные rolling histories не
накапливаются нигде: prior7/prior30 sums и число prior days равны 0, а
history_missing/cold_start равны 1 (персональный профиль выключен). Эти пять
колонок постоянны на train и после train-only стандартизации равны 0 во всех
split. Они сохранены в 71-колоночной схеме для контролируемого сравнения.

Volume deviation рассчитывается относительно общего train median/IQR,
novelty — относительно общего train vocabulary. Доступный календарный разрыв
между наблюдениями сохранён. Глобальные references batch-fitted на train,
без использования меток. Vocabulary включает текущие/будущие train-дни:
это offline account-holdout, а не будущий временной прогноз. В held-out state
не обновляется. Размер окна, labels, accounts/groups/split, обучение RF/IF/LSTM,
архитектура, сетка порогов и objective остаются прежними.

Исходная policy v1 и её SSD artifacts сохраняются как контроль. Ни один
неудачный результат или seed не удаляется. Dropout, weight decay, resampling,
добавление положительных окон в reconstruction fit и перебор параметров не
входят в этот эксперимент. Улучшение от новой policy заранее не предполагается.

## Проверка устойчивости

- Обе policy × RF/IF/LSTM × seeds 7, 21, 42, 84, 168: 30 записей кандидатов.
  Три готовых v1/seed42 кандидата повторно используются после проверки
  совместимости/хешей; 27 кандидатов обучаются заново.
- У всех основных кандидатов одинаковые 64 254 validation endpoint IDs и labels.
  Повторы меняют model randomness, сохраняя account split и feature state.
- Публикуются каждый seed, mean / sample std / min / max, paired differences.
  Пять seed не являются независимыми наборами данных или confidence intervals.
- Все checkpoint IDs, config/preparation/model hashes, thresholds и выбранные
  эпохи фиксируются отдельным immutable record перед будущим final.

## Реальная групповая CV внутри primary train

Три outer folds строятся только из исходных 600 train-аккаунтов с сохранением
incident-connected groups (`StratifiedGroupKFold`, seed 142). Внутри каждого
outer fit первая часть из пяти group-folds становится calibration; остальные
четыре — model/feature fit. Inner seeds: 243, 244, 245. Все части должны иметь
background и positive support; иначе отказ, без перебора удачного seed.

Для двух policy выполняется LSTM с model seed 42: ещё шесть кандидатов.
Каждый vocabulary/profile/scaler fit только на inner fit. Inner calibration
выбирает эпоху/порог. Outer assessment виден только отдельному evaluator,
который загружает замороженный checkpoint и применяет сохранённый порог.
Нельзя подбирать порог по outer assessment или переносить общий scaler из
основной подготовки в folds. CV-файлы называются `assessment.csv`, они
не являются реальным test проекта. Полные назначения и inputs сохраняются.

Группировка и fitting внутри folds следуют
[group-CV sklearn](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)
и [правилам исключения preprocessing leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage).
CV проверяет перенос между development-группами и дополняет пять model seeds.
Сценарий 3 имеет только одну независимую группу внутри primary train; наличие
его по обе стороны каждого fold невозможно и не обещается.

## Граница пункта

Реальный test не оценивается и не участвует в выборе policy/эпохи/порога.
Новая основная подготовка применяет train-fitted state ко всем split; само
преобразование test не является оценкой модели. Все training workers запрещают
открытие `test.csv`, включая хеширование. Raw, assignments и старые подготовки
не изменяются. Пункт 4 (frozen final test и итоговая оценка) остаётся отдельным.

## Воспроизведение

Требуется существующий SSD artifact root с исходными дневной и основной
подготовками из плана; минимум 20 GiB свободного места. Значения ниже —
каталоги, а не новые mountpoints. Новый запуск создаёт новый UUID-каталог.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
python3 src/run_cert_robustness.py --root "$ARTIFACT_ROOT" \
  --days "$CERT_DAYS" --preparation "$CERT_PREPARATION_V1" \
  --plan configs/cert_r4_2_robustness_v2.json
```

`plan.json` и source snapshot сохраняются до обучения. Отдельные процессы
ограничивают накопление памяти между trials; worker logs, исходы и затраты
сохраняются. Изменение исполняемых Python-файлов во время серии вызывает отказ.
Это фиксированная серия, не автоматический поиск параметров S6.

При продолжении после технического сбоя `--reuse-series` принимает каталог
той же серии-плана и создаёт **новый** UUID-каталог. Переиспользуются только
завершённые artifacts с совпадающими config/preparation и проверенными хешами;
несколько подходящих кандидатов вызывают отказ, а не выбор по качеству.
Старые failed status и логи сохраняются. Это не возобновление частично
обученного checkpoint и не общий job manager.

### Измеренная проблема истории устранена

Независимая сверка подтвердила одинаковые исходные 61 числовой base input,
ID/labels и global vocabulary/volume reference между policy. Только правила
истории и зависящие от них 10 преобразованных колонок отличаются. В новой
подготовке все пять availability/rolling колонок равны 0 после стандартизации
на train и validation; число endpoint-дней не менялось.

На выбранных seed 42 checkpoints, на тех же 63 968 all-background validation
окнах, доля squared error этих пяти признаков снизилась с **87,534%** до
примерно **0,000000145%**. MSE: 8,262990 → 0,239294. Для global-only выбранной
эпохи train MSE=0,225806, validation background MSE=0,239294, positive endpoint
MSE=0,459624. Фоновая reconstruction переносится гораздо лучше, но положительные
дни всё ещё плохо отделяются от тяжёлого хвоста background. Снижение MSE само
по себе не является доказательством качества detection; основные таблицы выше
используют неизменённые labels и cohort.

### Оценка и следующие действия

Приоритетное исправление подтверждено: модель перестала считать отсутствие
персональной истории главным источником reconstruction error. Для RF выросла
PR-AUC и уменьшился разброс F1 по model seed. Для LSTM устранён большой разрыв
background train/validation, поэтому добавлять dropout или weight decay без
отдельного обоснования сейчас не требуется. Они в этой серии не включались.
Это не гарантия отсутствия переобучения: outer CV остаётся слабой и неоднородной.

Качество IF/LSTM недостаточно для практической системы. Следующая отдельная
гипотеза для улучшения — одинаковая causal-online история во всех split,
использующая только наблюдения до текущего дня и никаких прошлых/будущих меток;
она потребует нового именованного протокола и проверки по группам. Её нельзя
подменить fit персонального профиля на полной held-out истории. В этой серии
такой третий вариант не запускался. Выбор рабочего баланса recall/FP тоже
требует явного objective до нового эксперимента, а не скрытой правки порогов.

Независимая финальная test-оценка текущих frozen configurations относится к
**пункту 4**, который не выполнялся. После её просмотра нельзя объявлять тот же
test нетронутым holdout для дальнейшего подбора.

Дополнительные проверки: все 30 frozen checkpoint hashes сверены, все 36
worker guards не зафиксировали обращений к test, CV confusion matrices/F1
пересчитаны по сохранённым predictions, общий cohort hash у всех основных
кандидатов одинаков. Проверены Unicode IDs, numerical inputs и membership,
background training filter, reload, provenance, source/config bindings.
Все **45 тестов прошли**; syntax, локальные ссылки и whitespace проверены.
